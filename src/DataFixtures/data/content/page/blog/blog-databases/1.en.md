## Migrations written twice

Doctrine describes the entities once, but the SQL generated for migrations depends on the database. The same table is created with `INT AUTO_INCREMENT` on MySQL and with `GENERATED BY DEFAULT AS IDENTITY` on PostgreSQL, and indexes are declared inside the create statement on one side and separately on the other.

Each Nathéo migration therefore exists twice, with the same version number. They are stored by minor version of Nathéo, for example in `migrations/V2.1/Mysql` and `migrations/V2.1/Postgresql`. When migrations run, a dedicated class looks at the platform of the connection and loads only the matching folders. A second class sorts the migrations by their number, which holds the date, whatever folder they are in.

Each file also starts with a platform check. A MySQL migration run by mistake on PostgreSQL is skipped instead of failing halfway.
