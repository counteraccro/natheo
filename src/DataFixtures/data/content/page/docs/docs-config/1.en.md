## System options

Site settings are made in the administration, from the "System options" menu of the "System" section. Options are sorted into categories.

- Website: the name and address of the site, the default language, the public site theme, whether it is open to the public, and the footer content, with links to social networks.
- SEO: options that ask search engines not to index the site or not to follow its links.
- Administration: page validation, confirmation before leaving a form, the number of rows in tables and permission to delete data.
- API: whether the API is open and how long user sessions last.
- Comments: whether comments are open and whether new comments must be approved.

The Media library, Emails, Notifications and Logs categories set where files are stored, the sender of emails, the purge of notifications and the history of database changes.

As long as the "Open the site to the public?" option is off, visitors see a holding page instead of the site.

## The database

The `.env` configuration targets MariaDB. For PostgreSQL, change `DATABASE_URL` and enable the `pdo_pgsql` extension. Nathéo detects the platform and loads the migrations that match it. The [database page](https://counteraccro.github.io/natheo.doc/Docs/Demarrage/base_de_donnees.html) of the documentation gives the details.

## Background tasks

Sending emails and exporting the database from the "Database" tool go through a Messenger queue. For these tasks to be processed, a process must run continuously.

```bash
php bin/console messenger:consume async
```

In production, run it with a process manager such as Supervisor, and set `MAILER_DSN` in `.env.local` to send emails.

## Overriding the API and the administration

The API and the administration screens can be customised without changing Nathéo's code. Your code goes in `src/Overwrite/` for PHP and in `assets/overwrite/` for screens.

### An API operation

Each API operation has a name, shown in the API documentation (`info_get`, `admin_tag_patch`…). In `config/cms/overwrite.yaml`, an entry gives an operation another provider for a read, or another processor for a write. The operation keeps its address and its rights.

```yaml
overwrite:
    api:
        - operation: info_get
          provider: App\Overwrite\Api\State\Provider\System\InfoProvider
```

The replacement class receives the original provider in its constructor, calls it, then completes its response. The file is read when the cache is built. After a change in production, run `php bin/console cache:clear`, which rejects an unknown operation or a class that does not exist.

### An administration screen

A file placed in `assets/overwrite/vue/Components/Admin/` replaces the file with the same path in `assets/vue/Components/Admin/`. For example, `assets/overwrite/vue/Components/Admin/Ui/Form/UiButton.vue` replaces the button of the whole back-office. A new screen is declared in a `module.ts` in `assets/overwrite/vue/Components/Admin/Modules/<Module>/`, and its module class, which sets the required role and the menu entry, in `src/Overwrite/Module/`. Run `yarn build` again after each addition.

### The bundled example

Nathéo ships with an example. The provider of `GET /api/v2/info` is overridden to fill the `extra` field, and the "Override example" screen of the "Tools" section, open to the super administrator, shows this response. To remove it, delete its entry from `config/cms/overwrite.yaml` and the files listed on its screen.
