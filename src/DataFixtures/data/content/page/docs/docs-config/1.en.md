## System options

Site settings are made in the administration, from the "System options" menu of the "System" section. Options are sorted into categories.

- Website: the name and address of the site, the default language, the public site theme, whether it is open to the public, and the footer content, with links to social networks.
- SEO: options that ask search engines not to index the site or not to follow its links.
- Administration: page validation, confirmation before leaving a form, the number of rows in tables and permission to delete data.
- API: whether the API is open and how long user sessions last.
- Comments: whether comments are open and whether new comments must be approved.

The Media library, Emails, Notifications and Logs categories set where files are stored, the sender of emails, the purge of notifications and the history of database changes.

As long as the "Open the site to the public?" option is off, visitors see a holding page instead of the site.

## The database

The `.env` configuration targets MariaDB. For PostgreSQL, change `DATABASE_URL` and enable the `pdo_pgsql` extension. Nathéo detects the platform and loads the migrations that match it. The [database page](https://counteraccro.github.io/natheo.doc/Docs/Demarrage/base_de_donnees.html) of the documentation gives the details.

## Background tasks

Sending emails and exporting the database from the "Database" tool go through a Messenger queue. For these tasks to be processed, a process must run continuously.

```bash
php bin/console messenger:consume async
```

In production, run it with a process manager such as Supervisor, and set `MAILER_DSN` in `.env.local` to send emails.

## Overriding an administration screen

An administration screen can be replaced with your own without changing Nathéo's code. The new controller goes in `src/Overwrite/Controller/`, whose routes are loaded automatically, and its templates in `templates/overwrite/`. It extends `AppAdminController`, like the original controllers.

The mapping is declared in `config/cms/overwrite.yaml`. When the original route is called, Nathéo redirects to the replacement route, copying the listed parameters under their new name.

```yaml
overwrite:
    - controller: App\Controller\Admin\DashboardController
      route: admin_dashboard_page_demo
      overwrite:
          route: admin_overwrite_page_demo
          parameters:
              param: id
```

This example ships with Nathéo. It replaces a demo page of the dashboard with the one from `DemoOverwriteController`, available to the super administrator from the "Override example" menu of the "Tools" section.
