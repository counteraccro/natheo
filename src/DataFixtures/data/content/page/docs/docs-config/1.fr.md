## Les options système

Les réglages du site se font dans l'administration, depuis le menu « Options système » de la partie « Système ». Les options sont rangées par catégories.

- Site web : le nom et l'adresse du site, la langue par défaut, le thème du site public, son ouverture au public et le contenu du pied de page, avec les liens vers les réseaux sociaux.
- SEO : les options qui demandent aux moteurs de recherche de ne pas indexer le site ou de ne pas suivre ses liens.
- Administration : la validation des pages, la confirmation avant de quitter un formulaire, le nombre de lignes des tableaux et l'autorisation de supprimer des données.
- API : l'ouverture de l'API et la durée des sessions des utilisateurs.
- Commentaires : l'ouverture des commentaires et la validation obligatoire des nouveaux commentaires.

Les catégories Médiathèque, Emails, Notifications et Logs règlent l'emplacement des fichiers, l'expéditeur des emails, la purge des notifications et l'historique des changements en base.

Tant que l'option « Ouvrir le site au public ? » est désactivée, les visiteurs voient une page d'attente à la place du site.

## La base de données

La configuration de `.env` vise MariaDB. Pour PostgreSQL, changez `DATABASE_URL` et activez l'extension `pdo_pgsql`. Nathéo détecte la plateforme et charge les migrations qui lui correspondent. La [page sur la base de données](https://counteraccro.github.io/natheo.doc/Docs/Demarrage/base_de_donnees.html) de la documentation donne les détails.

## Les tâches en arrière-plan

L'envoi des emails et l'export de la base depuis l'outil « Base de données » passent par une file Messenger. Pour que ces tâches soient traitées, un processus doit tourner en continu.

```bash
php bin/console messenger:consume async
```

En production, lancez-le avec un gestionnaire de processus comme Supervisor, et renseignez `MAILER_DSN` dans `.env.local` pour l'envoi des emails.

## Surcharger un écran de l'administration

Un écran de l'administration peut être remplacé par le vôtre sans modifier le code de Nathéo. Le nouveau contrôleur se place dans `src/Overwrite/Controller/`, dont les routes sont chargées automatiquement, et ses templates dans `templates/overwrite/`. Il étend `AppAdminController`, comme les contrôleurs d'origine.

La correspondance se déclare dans `config/cms/overwrite.yaml`. Quand la route d'origine est appelée, Nathéo redirige vers la route de remplacement, en recopiant les paramètres indiqués sous leur nouveau nom.

```yaml
overwrite:
    - controller: App\Controller\Admin\DashboardController
      route: admin_dashboard_page_demo
      overwrite:
          route: admin_overwrite_page_demo
          parameters:
              param: id
```

Cet exemple est livré avec Nathéo. Il remplace une page de démonstration du tableau de bord par celle de `DemoOverwriteController`, accessible au super administrateur depuis le menu « Exemple de surcharge » de la partie « Outils ».
