## Les options système

Les réglages du site se font dans l'administration, depuis le menu « Options système » de la partie « Système ». Les options sont rangées par catégories.

- Site web : le nom et l'adresse du site, la langue par défaut, le thème du site public, son ouverture au public et le contenu du pied de page, avec les liens vers les réseaux sociaux.
- SEO : les options qui demandent aux moteurs de recherche de ne pas indexer le site ou de ne pas suivre ses liens.
- Administration : la validation des pages, la confirmation avant de quitter un formulaire, le nombre de lignes des tableaux et l'autorisation de supprimer des données.
- API : l'ouverture de l'API et la durée des sessions des utilisateurs.
- Commentaires : l'ouverture des commentaires et la validation obligatoire des nouveaux commentaires.

Les catégories Médiathèque, Emails, Notifications et Logs règlent l'emplacement des fichiers, l'expéditeur des emails, la purge des notifications et l'historique des changements en base.

Tant que l'option « Ouvrir le site au public ? » est désactivée, les visiteurs voient une page d'attente à la place du site.

## La base de données

La configuration de `.env` vise MariaDB. Pour PostgreSQL, changez `DATABASE_URL` et activez l'extension `pdo_pgsql`. Nathéo détecte la plateforme et charge les migrations qui lui correspondent. La [page sur la base de données](https://counteraccro.github.io/natheo.doc/Docs/Demarrage/base_de_donnees.html) de la documentation donne les détails.

## Les tâches en arrière-plan

L'envoi des emails et l'export de la base depuis l'outil « Base de données » passent par une file Messenger. Pour que ces tâches soient traitées, un processus doit tourner en continu.

```bash
php bin/console messenger:consume async
```

En production, lancez-le avec un gestionnaire de processus comme Supervisor, et renseignez `MAILER_DSN` dans `.env.local` pour l'envoi des emails.

## Surcharger l'API et l'administration

L'API et les écrans de l'administration se personnalisent sans modifier le code de Nathéo. Votre code se place dans `src/Overwrite/` pour le PHP et dans `assets/overwrite/` pour les écrans.

### Une opération de l'API

Chaque opération de l'API porte un nom, visible dans la documentation de l'API (`info_get`, `admin_tag_patch`…). Dans `config/cms/overwrite.yaml`, une entrée donne à une opération un autre provider pour une lecture, ou un autre processor pour une écriture. L'opération garde son adresse et ses droits.

```yaml
overwrite:
    api:
        - operation: info_get
          provider: App\Overwrite\Api\State\Provider\System\InfoProvider
```

La classe de remplacement reçoit le provider d'origine dans son constructeur, l'appelle puis complète sa réponse. Le fichier est lu à la construction du cache. Après une modification en production, lancez `php bin/console cache:clear`, qui refuse une opération inconnue ou une classe qui n'existe pas.

### Un écran de l'administration

Un fichier placé dans `assets/overwrite/vue/Components/Admin/` remplace le fichier de même chemin de `assets/vue/Components/Admin/`. Par exemple, `assets/overwrite/vue/Components/Admin/Ui/Form/UiButton.vue` remplace le bouton de tout le back-office. Un nouvel écran se déclare dans un `module.ts` de `assets/overwrite/vue/Components/Admin/Modules/<Module>/`, et sa classe de module, qui fixe le rôle requis et l'entrée du menu, dans `src/Overwrite/Module/`. Relancez `yarn build` après chaque ajout.

### L'exemple livré

Nathéo est livré avec un exemple. Le provider de `GET /api/v2/info` y est surchargé pour remplir le champ `extra`, et l'écran « Exemple de surcharge » de la partie « Outils », réservé au super administrateur, affiche cette réponse. Pour le retirer, supprimez son entrée de `config/cms/overwrite.yaml` et les fichiers listés sur son écran.
