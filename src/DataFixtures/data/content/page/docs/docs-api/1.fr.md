## Obtenir un token

Un appel à l'API v2 demande un token. Créez-le dans l'administration, depuis le menu « Tokens API » de la partie « Système », avec le rôle qui correspond à votre usage : lecture, écriture ou administration. Le token s'envoie dans l'en-tête `Authorization: Bearer`. L'option « Ouvrir l'API ? » doit être activée.

## Trouver une page

Une page se recherche par son adresse, avec le filtre `slug` sur la collection des pages. La langue se choisit avec l'en-tête `Accept-Language` ou le paramètre `locale`.

```bash
curl -H "Authorization: Bearer <token>" \
     -H "Accept-Language: fr" \
     "https://votre-site.fr/api/v2/pages?slug=accueil"
```

La réponse est une collection Hydra qui contient 0 ou 1 page. Chaque page y apparaît avec un résumé : son identifiant, son titre, son auteur, ses tags et ses dates.

## Lire la page et ses blocs

L'appel à `/api/v2/pages/{id}` renvoie la page complète, avec sa disposition, ses informations SEO, ses menus et la liste de ses blocs. Chaque bloc est désigné par son IRI, par exemple `/api/v2/page_contents/476`. Cet appel renvoie le contenu du bloc, avec le Markdown déjà converti en HTML pour un bloc de texte.

Pour du JSON sans les champs Hydra, ajoutez l'en-tête `Accept: application/json`.

## Aller plus loin

La liste complète des ressources, de leurs paramètres et de leurs erreurs se trouve sur `/api/v2/docs`, où chaque appel peut être essayé avec votre token. Si vous utilisez encore l'API v1, le [guide de migration](https://counteraccro.github.io/natheo.doc/Docs/API/migration_v2.html) détaille les changements.
