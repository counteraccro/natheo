## Getting a token

A call to the API v2 requires a token. Create it in the administration, from the "API tokens" menu of the "System" section, with the role that matches your use: read, write or admin. The token is sent in the `Authorization: Bearer` header. The "Open the API?" option must be on.

## Finding a page

A page is looked up by its address, with the `slug` filter on the pages collection. The language is chosen with the `Accept-Language` header or the `locale` parameter.

```bash
curl -H "Authorization: Bearer <token>" \
     -H "Accept-Language: en" \
     "https://your-site.com/api/v2/pages?slug=home"
```

The response is a Hydra collection holding 0 or 1 page. Each page appears with a summary: its identifier, title, author, tags and dates.

## Reading the page and its blocks

A call to `/api/v2/pages/{id}` returns the full page, with its layout, SEO information, menus and the list of its blocks. Each block is referred to by its IRI, for example `/api/v2/page_contents/476`. That call returns the content of the block, with the Markdown already converted to HTML for a text block.

For JSON without the Hydra fields, add the `Accept: application/json` header.

## Going further

The full list of resources, their parameters and their errors is on `/api/v2/docs`, where each call can be tried with your token. If you still use the API v1, the [migration guide](https://counteraccro.github.io/natheo.doc/Docs/API/migration_v2.html) describes the changes.
