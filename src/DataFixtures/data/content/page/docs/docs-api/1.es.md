## Obtener un token

Una llamada a la API v2 necesita un token. Créelo en la administración, desde el menú «Tokens API» de la parte «Sistema», con el rol que corresponda a su uso: lectura, escritura o administración. El token se envía en la cabecera `Authorization: Bearer`. La opción «¿Abrir la API?» debe estar activada.

## Encontrar una página

Una página se busca por su dirección, con el filtro `slug` sobre la colección de páginas. El idioma se elige con la cabecera `Accept-Language` o con el parámetro `locale`.

```bash
curl -H "Authorization: Bearer <token>" \
     -H "Accept-Language: es" \
     "https://su-sitio.es/api/v2/pages?slug=inicio"
```

La respuesta es una colección Hydra que contiene 0 o 1 página. Cada página aparece con un resumen: su identificador, su título, su autor, sus etiquetas y sus fechas.

## Leer la página y sus bloques

La llamada a `/api/v2/pages/{id}` devuelve la página completa, con su disposición, su información SEO, sus menús y la lista de sus bloques. Cada bloque se designa por su IRI, por ejemplo `/api/v2/page_contents/476`. Esa llamada devuelve el contenido del bloque, con el Markdown ya convertido en HTML para un bloque de texto.

Para obtener JSON sin los campos Hydra, añada la cabecera `Accept: application/json`.

## Ir más lejos

La lista completa de los recursos, de sus parámetros y de sus errores está en `/api/v2/docs`, donde se puede probar cada llamada con su token. Si todavía usa la API v1, la [guía de migración](https://counteraccro.github.io/natheo.doc/Docs/API/migration_v2.html) detalla los cambios.
