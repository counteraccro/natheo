## Informar de un error o proponer una idea

Las issues se abren en [GitHub](https://github.com/counteraccro/natheo/issues/new/choose) a partir de un formulario, uno por tipo de solicitud. El formulario de error pide la versión de Nathéo, el entorno, el módulo afectado y el comportamiento esperado. Estas respuestas sirven para poner las etiquetas de la issue automáticamente, lo que permite clasificarla desde su creación.

Una pregunta de uso o una idea todavía poco definida tiene mejor sitio en las [discusiones de GitHub](https://github.com/counteraccro/natheo/discussions) o en [Discord](https://discord.gg/CgcMCcbmaR), donde puede hablar directamente con el mantenedor.

Un fallo de seguridad nunca debe describirse en una issue pública. Se comunica en privado con el formulario [Report a vulnerability](https://github.com/counteraccro/natheo/security/advisories/new) de GitHub o por mensaje privado en Discord. La [política de seguridad](https://github.com/counteraccro/natheo/blob/master/SECURITY.md) indica las versiones mantenidas y el plazo de respuesta, que es de 7 días como máximo.

## Contribuir al código

Cada tema sigue el mismo camino, con una issue, una rama con su número y una pull request vinculada a la issue. Los temas grandes se agrupan en una Epic, que tiene su propia rama. En cada pull request, GitHub Actions compila el front y luego ejecuta las pruebas PHPUnit en MySQL y en PostgreSQL. Las tres comprobaciones deben pasar antes del merge.

La [guía de contribución](https://github.com/counteraccro/natheo/blob/master/CONTRIBUTING.md) detalla las convenciones de nombres, las etiquetas y cómo se lleva el registro de cambios. Antes de empezar con un tema importante, pase por Discord para hablarlo.
