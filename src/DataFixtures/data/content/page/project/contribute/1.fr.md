## Signaler un bug ou proposer une idée

Les issues s'ouvrent sur [GitHub](https://github.com/counteraccro/natheo/issues/new/choose) à partir d'un formulaire, un par type de demande. Le formulaire de bug demande la version de Nathéo, l'environnement, le module concerné et le comportement attendu. Ces réponses servent à poser les labels de l'issue automatiquement, ce qui permet de la trier dès sa création.

Une question d'utilisation ou une idée encore floue a plutôt sa place dans les [discussions GitHub](https://github.com/counteraccro/natheo/discussions) ou sur le [Discord](https://discord.gg/CgcMCcbmaR), où vous pouvez échanger directement avec le mainteneur.

Une faille de sécurité ne doit jamais être décrite dans une issue publique. Elle se signale en privé avec le formulaire [Report a vulnerability](https://github.com/counteraccro/natheo/security/advisories/new) de GitHub ou en message privé sur Discord. La [politique de sécurité](https://github.com/counteraccro/natheo/blob/master/SECURITY.md) indique les versions suivies et le délai de réponse, qui est de 7 jours au plus.

## Contribuer au code

Chaque sujet suit le même chemin, avec une issue, une branche nommée d'après son numéro et une pull request liée à l'issue. Les gros sujets sont regroupés dans une Epic, qui a sa propre branche. Sur chaque pull request, GitHub Actions construit le front, puis lance les tests PHPUnit sur MySQL et sur PostgreSQL. Les trois vérifications doivent passer avant le merge.

Le [guide de contribution](https://github.com/counteraccro/natheo/blob/master/CONTRIBUTING.md) détaille les conventions de nommage, les labels et la tenue du journal des modifications. Avant de vous lancer sur un sujet important, passez sur le Discord pour en parler.
