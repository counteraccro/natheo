## Report a bug or suggest an idea

Issues are opened on [GitHub](https://github.com/counteraccro/natheo/issues/new/choose) from a form, one per type of request. The bug form asks for the Nathéo version, the environment, the module involved and the expected behavior. These answers are used to set the labels of the issue automatically, so it can be sorted as soon as it is created.

A usage question or an idea that is still vague belongs in [GitHub discussions](https://github.com/counteraccro/natheo/discussions) or on [Discord](https://discord.gg/CgcMCcbmaR), where you can talk directly with the maintainer.

A security vulnerability must never be described in a public issue. Report it privately with the GitHub [Report a vulnerability](https://github.com/counteraccro/natheo/security/advisories/new) form or in a private message on Discord. The [security policy](https://github.com/counteraccro/natheo/blob/master/SECURITY.md) lists the supported versions and the response time, which is 7 days at most.

## Contribute to the code

Every topic follows the same path, with an issue, a branch named after its number and a pull request linked to the issue. Larger topics are grouped in an Epic, which has its own branch. On every pull request, GitHub Actions builds the front end, then runs the PHPUnit tests on MySQL and on PostgreSQL. All three checks must pass before the merge.

The [contribution guide](https://github.com/counteraccro/natheo/blob/master/CONTRIBUTING.md) describes the naming conventions, the labels and how the changelog is kept. Before starting on a large topic, drop by Discord to talk about it.
